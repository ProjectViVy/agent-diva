# Agent-Diva 核心模块重构提案 (待审核)

> **提案日期**: 2026-07-16
> **提案目的**: 列出由代码质量审查工具及静态扫描得出的高风险代码债务，供团队进行后续的人工核验与重构排期。
> **前置说明**: 本提案列出的所有“圈复杂度”、“行数”和“API泄漏问题”均来源于静态分析报告，需要技术委员会进一步 Review 确认是否需要立即干预。

---

## 1. `agent-diva-agent` 模块重构提案

### 1.1 拆分超大消息循环
* **受影响文件**: `src/agent_loop/loop_turn.rs`
* **待核验现象**: `process_inbound_message_inner` 函数长达 1221 行，承担了超过 10 种独立逻辑（安全检查、LLM流式调用、计划审批、附件解析等）。
* **重构建议**: 采用门面模式（Facade）和独立的预处理器策略，将其按生命周期阶段拆分为多个单一职责的模块。

### 1.2 消除异步上下文阻塞
* **受影响文件**: `src/context.rs`
* **待核验现象**: 在组装系统提示词的 `read_trimmed_markdown` 逻辑中，直接使用了同步的 `std::fs::read_to_string`。这会随着消息循环的高频调用，阻塞 Tokio 工作线程。
* **重构建议**: 替换为 `tokio::fs` 的全异步调用，或将其移至 `spawn_blocking` 中执行。

## 2. `agent-diva-manager` 模块重构提案

### 2.1 修复 HTTP 控制面大文件阻塞假死
* **受影响文件**: `src/handlers/logs.rs` 和 `src/handlers/audit.rs`
* **待核验现象**: `scan_audit_files` 和 `read_log_lines` 包含了密集的同步目录遍历（`read_dir`）和同步文件读取操作。挂载在 Axum 异步路由上会导致并发吞吐量断崖式下跌。
* **重构建议**: 将大文件日志解析流程移入专门的后台队列，或使用异步文件流返回结果。

### 2.2 修复 API 防腐层缺失
* **受影响文件**: `src/handlers/` 下的大部分路由函数
* **待核验现象**: 大量 HTTP API 直接序列化 `agent-diva-core` 中的内部领域实体（如 `PlanReportDetail`）进行返回，导致内部与外部 API 强耦合。
* **重构建议**: 引入专门的 DTO (数据传输对象) 层（例如 `api::responses`），负责从内部模型到外部 API JSON 视图的转换。

---

## 3. `agent-diva-cli` 模块重构提案

### 3.1 拆解高复杂度启动函数
* **受影响文件**: `src/main.rs`
* **待核验现象**: `async_main` 函数的圈复杂度（Cognitive Complexity）高达 177，包含了庞大而臃肿的参数解析、环境降级策略、通道注入逻辑。
* **重构建议**: 抽取专门的 `BootstrapManager`，将环境检测、配置加载、本地引擎启动逻辑彻底模块化。

---

## 4. `agent-diva-core` 模块重构提案

### 4.1 杜绝状态回退导致的静默数据丢失
* **受影响文件**: `src/soul/mod.rs` 等持久化加载组件
* **待核验现象**: 在执行 `load()` 时使用了 `unwrap_or_default()` 兜底。一旦读取抛出瞬时 IO 错误（如文件锁、权限不足），将退避为 Default 空状态，并在下一次落盘时永久覆写销毁原有用户数据。
* **重构建议**: 必须显式处理 `Result`，遇到读异常时中断进程或明确抛给上层，严禁使用空数据退避存盘。

### 4.2 核心库禁用字符串化报错
* **受影响文件**: `src/planning/report_store.rs`
* **待核验现象**: 核心基础包内部依赖了 `anyhow::Result` 并高频抛出 `anyhow!("plan draft not found")` 等字符串错误，导致调用方无法安全地编写 `match` 恢复分支。
* **重构建议**: 在基础包级别全面废弃 `anyhow`，使用 `thiserror` 规范化定义 `enum PlanError` 等强类型返回结构。

---

## 5. `agent-diva-gui` 模块重构提案

### 5.1 Tauri IPC 通道防腐层构建
* **受影响文件**: `src-tauri/src/commands.rs`
* **待核验现象**: 同样缺乏模型防腐层，直接将底层领域模型暴露给前端，且文件中包含近 10 个未清理的旧版网关进程控制兼容函数。
* **重构建议**: 为 Tauri 事件与命令响应构建专属的 `ViewModel`；统一清剿 `#[allow(dead_code)]` 掩盖下的废弃兼容层方法。

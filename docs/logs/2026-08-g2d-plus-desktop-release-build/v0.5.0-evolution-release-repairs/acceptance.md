# Acceptance

1. Start the newly built desktop executable with the isolated acceptance profile.
2. Open **Evolution → Runs** and confirm previous runs are visible immediately, with local-time display and UTC retained in the tooltip.
3. Trigger a reflection only with operator-authorized provider credentials and evidence available.
4. Confirm a model response containing JSON (including an optional fenced response) either produces review-only candidates or a clear fail-closed diagnostic; it must never directly write typed Memory.
5. Review any proposal before approving a durable change.

G2D+ final acceptance remains open until the real provider/evidence/proposal and upgrade-profile scenarios have been manually completed.

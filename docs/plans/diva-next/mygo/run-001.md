A source-read or Linux native pass is not a Windows/provider/product pass.

## Exact upstream API notes

All source paths below refer to the
[pinned upstream tree](https://github.com/egoist/mygo/tree/154449f603ede999a1dfc8692717de62f7bacf12).

| Surface | Signature/behavior at the pin | Integration consequence |
| --- | --- | --- |
| app.go | App.Run() error; WhenReady(func()); OnBeforeQuit(func(*QuitEvent)); OnWillQuit(func(*QuitEvent)); OnQuit(func()); Quit() | Run on main goroutine. BeforeQuit is preventable; acquire Host only after readiness. OnQuit is after loop shutdown, not a place for a second teardown. |
| window.go | Window.Close/Hide/Show(); OnClose(func(*CloseEvent)); OnClosed(func()); Page.OnDidNavigate(func(string)); Page.OnWillNavigate(func(*NavigateEvent)) | Close can be prevented and mapped to hide. Committed navigation resets page context; reload skips WillNavigate, so revocation must also handle DidNavigate. |
| ipc.go | Bind(...any); BindAs(string, any); CallerWindow(context.Context) *Window | Bind the facade before Run; caller key is private and belongs to bound-method context. Do not infer a native sender from JSON/windowId. |
| channel.go | Channel[T].Send(T) error; Close(); ErrChannelClosed | Closing the page channel cancels its call context and unblocks Send; one MiB flow control exists. Product Next admission/queue/gap remains SDK work. |
| protocol.go | Protocol.Handle(string, http.Handler) error; HandleFunc; Unhandle | Register before windows are created. serveScheme assigns RemoteAddr="mygo:"+native window ID. HTTP context does not carry CallerWindow. Never mount this handler on a network server and trust arbitrary RemoteAddr. |
| permissions.go | Page.SetPermissionHandler(func(PermissionRequest) bool); request has Permissions and Origin | Default grants trusted pages; product must apply its accepted policy and native OS permission handling. Probe explicitly denies access. |
| single_instance.go | App.RequestSingleInstanceLock() bool; OnSecondInstance(func(args []string, workingDir string)) | Must precede real Host.Open; false means do not acquire a Host. Availability inspected, second process not exercised. |

MYGO_GENERATE is checked at the start of App.Run, before backend initialization
or WhenReady callbacks. The probe binds reflection-only methods first and owns
its root only in WhenReady. Generation counters are instrumentation, not an
assertion that a proposed product Host already compiles.

## Reproduction

From `experiments/mygo/probe`, with Go 1.27.1, Node/npm and network available:

```sh
./verify.sh
```

This runs module checks, vet/format, uncached unit/race/no-CGO tests, default and
no-CGO builds, a Windows cross-build, configured CLI generation, frozen npm
install with scripts disabled and generated-client typecheck. Builds are ignored
under `build/`. Do not use these unsealed executables as product releases.

For native Linux, install GTK3, WebKitGTK 4.1 and Xvfb. In a normal desktop
session run `./verify.sh --native`, or use:

```sh
MYGO_PROBE_NATIVE=1 xvfb-run -a go test -count=1 -v -run '^TestNative' -timeout 60s ./...
```

For Windows, install the pinned Go compiler and WebView2; in PowerShell:

```powershell
$env:MYGO_PROBE_NATIVE = '1'
go test -count=1 -v -run '^TestNative' -timeout 60s ./...
Remove-Item Env:MYGO_PROBE_NATIVE
```

These are reproduction instructions, not claims that Windows was run here.
The ordinary `go test ./...` skips the native suite explicitly; it is not GUI proof.
An independent 75-second event-loop watchdog covers native startup and an
additional 10-second watchdog bounds Quit after m.Run returns, when Go has
stopped its ordinary test timer. A forced-timeout child test checks exit 124.
Send attempt/completion counters must stop beyond the flow-control threshold
for 200 ms before channel cancellation; a mere sleep is insufficient proof.
The native TestMain verifies one root close and no active calls after App.Run,
even though the Quit itself necessarily happens after the test function returns.

This execution downloaded native debs and extracted them locally; no system
package install or service change was required. The sandbox forbids setuid and
Unix socket binding: apt download used Sandbox::User=root, and Xvfb/Go tests ran
in the same command network namespace over a private local TCP display.
Temporary helper symlinks satisfied compiled absolute executable paths; Xvfb was
terminated after every run. No WebKit sandbox-disabling flag was used. EGL/DRI3
warnings reflect software rendering, not a measured production GPU result.

Initial failures were recorded before green verification: missing newProbe;
Xvfb library/helper/socket prerequisites; separate command network namespaces;
an exact framework error-message assertion and stale-returning-page readiness
assertion. Fixes addressed those causes. Task 2 separately failed the generation
report assertions before adding nativeReady/windows instrumentation, then passed.

## Sealed SDK and packaging handoff

W2 must produce its accepted source resolver, `--target go-host`, host directory,
package/assets/source-lock validation, source snapshots, temporary consumer
modfile carrying the transitive local replace closure, and generated dependency
assembly/manifest overlay. Both tests and generation must use those same staging
inputs. Research Go 1.27.1 must be explicitly reconciled with W2's 1.26.4 baseline;
this run cannot silently approve that product compiler change.

Build the frontend once from its frozen product lock, then ask the existing
Generation compiler to build and Inspect the exact MyGo host. Resolve the clean
host commit in an untracked build report; never track a self-referential host SHA.
The standalone probe's dirty development build has no Generation ID or seal.

At the pin, `cmd/mygo/build.go` calls buildBinary/go build for every target,
constructs an embedding overlay and injects package flags. Windows resources
are materialized as .syso in the main package before compilation (Go overlay
does not replace that file). `--skip-build-command` skips only the frontend
command; it does not skip Go compilation. Therefore stock `mygo build` is not
packaging-only and must not wrap a sealed product executable.

W6 packaging must accept the exact already-sealed executable, preserve its
Inspect identity/hash, supply an experimental application ID/profile, installer
resources and WebView2 prerequisites, and re-Inspect the final packaged artifact.
Windows icon/version/manifest/link flags must be agreed inputs before sealed
compilation, not applied by a later recompiling CLI. Signing variance must be
recorded. No installer, updater, NSIS download or signing was run in MYGO-001.

## Cost and decision

Measured work here is one small standalone nested module, one generated facade,
two locked npm packages, focused Go and native lifecycle checks,
and local compiler/native dependency setup. This is feasibility/setup effort;
it is not a recurring upkeep estimate or a Wails performance comparison.
Keep the research lane parked at this reproducible probe until Windows and the
accepted W1/W2/W3 outputs exist. Reevaluate only affected gates on a new candidate
or accepted SDK/media/build interface change. Do not start a second production
runtime or weaken contracts to advance a blocked Story.

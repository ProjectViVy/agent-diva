# W2: Sealed Go-host packaging — Implementation Plan

> For agentic workers: after implementation authorization, use
> **superpowers:executing-plans** task by task. Use delegation only when explicitly
> authorized. This planning publication does not start product implementation.

**Goal:** Build the external DIVA executable through the VIVY Generation compiler with reproducible replacement closure and verifiable host/frontend identity.

**Architecture:** [DN-W3](../p0-design.md#dn-w3-go-owned-desktop-migration-2026-10-04)
with one Go desktop owner, one sealed VIVY runtime and the retained frontend.

**Tech stack:** Go 1.26.4, pinned Wails v3 candidate from W0, Vue/TypeScript,
existing VIVY SDK/Generation and native OS facilities.

**Spec:** [Existing shared ledger](../backend-separation-contracts.md#w3-go-host-contracts).
W3-4 input lock, new CLI flags, snapshot/modfile/overlay semantics and output; W3-1 mandatory sealing.

**Status:** Blocked by W1 public host evidence.

**Immediate prerequisites:** W1.
The [index](../index.md#executable-story-package) owns live readiness.
**Requirement coverage:** W-R2, W-R6.

## Global constraints

Preserve single Runtime/Journal, sealed assembly, authenticated control/grants,
native sender identity and existing cancellation rules. No Agent rewrite,
historical import, second daemon, browser secrets/provider HTTP or permanent
dual host. Existing files listed below were verified against the frozen source
trees; proposed paths do not exist at that baseline. Reconcile source drift
before execution and serialize shared files. Tests/commands in this Plan are
future implementation gates, not results of this documentation publication.

## Tasks

### Task 1: Prove the dependency-resolution failure and fixture

- [ ] Create an external Go host fixture importing sdk/host/v1. Demonstrate dependency replace directives are not inherited, then capture the pinned source closure needed to resolve agent-vivy modules and sibling Laputa packages. Use existing source resolver and generated assembly functions. Confirm current executable pack tests before changes.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 2: Extend the existing pack target parser

- [ ] Add --target go-host and W3-4 --host-dir/--host-package/--host-assets/--host-lock validation. Reject traversal, missing source pins, dirty release input, invalid targets and output reuse. Make host inputs relative to documented roots. Retain existing executable/shared targets until W6. Add focused parser/negative tests, not just happy-path fixture snapshots.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 3: Create the sealed external consumer build

- [ ] Snapshot host/VIVY/sibling sources; generate a temporary consumer modfile with required replacement closure. Overlay generated VIVY assembly and manifest at paths actually used by the dependency compiler. Select VIVY headless without building its unused web face. Consume the frontend tree built once by the DIVA wrapper from its frozen pnpm lock and bind those final bytes; pack must not rebuild it. Go builds the real host package, never a second unsealed entrypoint.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 4: Version host provenance and Inspect together

- [ ] Implement the exact optional hostBuild object and vivy.go-host/v1 validation/hashing/reader behavior from W3-4. Update every strict decoder and public reader; legacy executable artifacts without hostBuild remain supported. Include source tree digests, locks, compiler/tools/platform, selected module conformance and host assets. Extend Inspect to extract the manifest from the external executable without running it and verify the corresponding artifact tree. Keep previous executable artifacts inspectable.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 5: Exercise tamper and reproducibility gates

- [ ] Change recipe, source hash, module, consumer modfile, selected provider, frontend byte and embedded/sidecar manifest individually; each must fail compile or Inspect as appropriate. Build from two clean unrelated paths and compare normalized inputs/Generation IDs; document unavoidable platform/signing byte variance rather than promise bit-identical signed binaries. Record dependency/native CGO/toolchain needs.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 6: Add DIVA staging wrapper

- [ ] Create scripts/build-desktop.py and dependency source lock only after the new target works. Resolve the clean DIVA host commit at build time into the separate build report, never a self-referential tracked pin. The wrapper has the W3-4 build/test modes, stages exact commits into task-local directories, and passes the resolved temporary consumer modfile to both Go builds and Go race tests. Build mode runs frozen frontend install/build and the new pack target and produces a build report. No developer absolute replace entry, go work leakage, floating main, disabled checksum verification or binary download as the runtime dependency.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

From a staged clean source pair, run the W3-4 pack/inspect commands; compare a second pack in a different directory. ## Exit gate and handoff

The external host target demonstrably links generated assembly, accounts for local replacements and host/frontend content, rejects tampering, and passes VIVY CI. W3 cannot bypass this release path even if ordinary go build starts successfully.

## Review focus

Check actual compiler dependency paths, headless UI exclusion, manifest schema compatibility, checksum/source-lock integrity and packaging tools accidentally rebuilding another executable.

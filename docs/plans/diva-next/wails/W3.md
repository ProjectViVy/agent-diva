**Goal:** Run the existing DIVA frontend over the sealed Go host, with one native lifetime owner and preserved window behavior.

**Architecture:** [DN-W3](../p0-design.md#dn-w3-go-owned-desktop-migration-2026-10-04)
with one Go desktop owner, one sealed VIVY runtime and the retained frontend.

existing VIVY SDK/Generation and native OS facilities.

**Spec:** [Existing shared ledger](../backend-separation-contracts.md#w3-go-host-contracts).
W3-1 host consumer; W3-2 CallReply/events/lifecycle; W3-3 verified primary-window capability.

**Status:** Blocked by W0 native GO and W2 sealed external build.

**Immediate prerequisites:** W0, W2.
The [index](../index.md#executable-story-package) owns live readiness.
**Requirement coverage:** W-R1, W-R3, W-R5, W-R9.

## Global constraints

Preserve single Runtime/Journal, sealed assembly, authenticated control/grants,
native sender identity and existing cancellation rules. No Agent rewrite,
historical import, second daemon, browser secrets/provider HTTP or permanent
dual host. Existing files listed below were verified against the frozen source
trees; proposed paths do not exist at that baseline. Reconcile source drift
before execution and serialize shared files. Tests/commands in this Plan are
future implementation gates, not results of this documentation publication.

## Tasks

### Task 1: Adopt proven native APIs, then wire a single owner

- [ ] Consume W0's exact pinned signatures and W2's sealed build. The entrypoint loads explicit absolute fresh Next config/data paths independent of cwd. Compose Desktop and one VIVY public Host; partial failure unwinds without publishing ready. Do not import agent-vivy/internal or manually register runtime modules. Embed the frontend through agent-diva-gui/assets.go.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 2: Adapt the native seam and event pump

- [ ] Generate Wails bindings only into the prescribed directory. Keep vivyCall/onVivyEvent public TypeScript behavior and use CallReply normalization. Replace createTauriTransport with a Wails implementation behind VivyTransport, without rewriting client/stores. Use one listener-install promise; one Go pump calls blocking Next and emits vivy:event. Dispose/reload listener tests prove no duplicate callbacks or runtime close.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 3: Preserve presentation behavior and native actions

- [ ] Inventory all actual Tauri imports from the source tree, including window, dialog, clipboard/opener and dormant frontend modules. Route retained native actions through desktop-host.ts with W0-proven APIs. Keep Vue, VRM, layout and business interactions. Browser mode reports desktop-only capability unavailable instead of silently making provider calls or starting another backend.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 4: Implement hide, reopen and Quit explicitly

- [ ] Window close hides and keeps VIVY alive. Hide/reload invalidates voice context and stops JS audio. Reopen resubscribes and fetches sessions/runs/approval/diagnostics projections with gap handling, without replay speech. Explicit Quit closes admission, calls the single coordinator with one deadline, stops producers and reports incomplete teardown truthfully. Test quit during model call, subscription recovery and tray activity.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 5: Add single-instance and caller boundaries

- [ ] Reject a second process opening the same profile before runtime startup; activate the existing primary window using pinned native support. Block privileged bindings on external navigation and foreign windows; pet expansion stays deferred. Verify no old-home discovery/copy/delete, no shared VIVY library loading and no Wails imports beyond the frontend seam/generated files.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 6: Build the sealed desktop candidate

- [ ] Use scripts/build-desktop.py and W3-4 to produce the actual Wails desktop executable with DIVA UI bytes in the manifest. Confirm native package steps use that executable. Record source pins, native tool versions, generation and artifact hashes. Keep all changes on the migration branch until W5 parity gates pass.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Final task: evidence, review and scoped commit

- [ ] Run the focused checks below and applicable repository-required gates.
- [ ] Review the diff against the shared ledger and this Story's exit criteria.

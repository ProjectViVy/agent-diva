# W1: Public VIVY Go host and lifetime — Implementation Plan

> For agentic workers: after implementation authorization, use
> **superpowers:executing-plans** task by task. Use delegation only when explicitly
> authorized. This planning publication does not start product implementation.

**Goal:** Expose the existing sealed runtime through a narrow public Go API and remove foreign-ABI ownership from the embedding lifecycle.

**Architecture:** [DN-W3](../p0-design.md#dn-w3-go-owned-desktop-migration-2026-10-04)
with one Go desktop owner, one sealed VIVY runtime and the retained frontend.

**Tech stack:** Go 1.26.4, pinned Wails v3 candidate from W0, Vue/TypeScript,
existing VIVY SDK/Generation and native OS facilities.

**Spec:** [Existing shared ledger](../backend-separation-contracts.md#w3-go-host-contracts).
W3-1 public signatures, bounds, typed errors and close semantics; W3-5 logging/admission obligations.

**Status:** Planned; implementation authorization is outside this documentation publication.

**Immediate prerequisites:** None.
The [index](../index.md#executable-story-package) owns live readiness.
**Requirement coverage:** W-R1, W-R2, W-R5.

## Global constraints

Preserve single Runtime/Journal, sealed assembly, authenticated control/grants,
native sender identity and existing cancellation rules. No Agent rewrite,
historical import, second daemon, browser secrets/provider HTTP or permanent
dual host. Existing files listed below were verified against the frozen source
trees; proposed paths do not exist at that baseline. Reconcile source drift
before execution and serialize shared files. Tests/commands in this Plan are
future implementation gates, not results of this documentation publication.

## Tasks

### Task 1: Freeze host tests at the actual control boundary

- [ ] Use W3-1 signatures verbatim. Create tests for valid sealed opening, absent/corrupt Generation, startup failure unwinding, second live owner, post-close rejection and unchanged trusted RPC authorization. Construct a minimal generated fixture through existing assembly machinery, not a hand-wired unsealed app. Test external SDK imports from a different module to ensure internal types do not leak.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 2: Implement the public facade

- [ ] Read/validate the absolute config path inside VIVY. Export only the W3-1 types, preserving method/result schemas and safe RPC code/data. Keep internal DialControl and ActionHost caller identity/grants. Limit encoded requests before dispatch and preserve context cancellation/unknown write outcome. Initialize owned runtime logging once; CLI behavior must not gain duplicate writers.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 3: Replace periodic polling with blocking notification delivery

- [ ] Add a context-aware blocking Next path to the embedded queue, keeping existing Poll only during the short C ABI source transition. Exercise empty wait, first notification, max batch, overflow sticky gap, gap-only wakeup, close while waiting and simultaneous producer/drain. A full queue must never stall control dispatch. Exactly one desktop reader is supported.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 4: Propagate one bounded close operation

- [ ] Add a context-aware embedded/app close path while retaining existing CLI wrapper semantics. Separate state admission from call execution; no mutex held across RPC/model work. Stop automatic producers before stores close; cancel and join callers/event pump; close peer, cognitive/observer/MCP/memory/storage owners once. Audit every blocking close for deadline propagation. Tests must distinguish successful release from timeout with live resources.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 5: Verify current cognitive lifecycle and logging

- [ ] StartEmbeddedServices already starts the cognitive loop at this base: preserve and test it rather than adding a duplicate. Verify automatic services stop once and runtime diagnostics are emitted in embedded mode with redaction/rotation. Leave fresh FrozenCore/restart semantic reproduction to W5 without declaring those findings fixed.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Final task: evidence, review and scoped commit

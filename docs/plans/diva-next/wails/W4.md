# W4: DIVA Go speech and media — Implementation Plan

> For agentic workers: after implementation authorization, use
> **superpowers:executing-plans** task by task. Use delegation only when explicitly
> authorized. This planning publication does not start product implementation.

**Goal:** Port current native speech behavior to Go while preserving credentials, media quotas, cancellation and stale-result guarantees.

**Architecture:** [DN-W3](../p0-design.md#dn-w3-go-owned-desktop-migration-2026-10-04)
with one Go desktop owner, one sealed VIVY runtime and the retained frontend.

**Tech stack:** Go 1.26.4, pinned Wails v3 candidate from W0, Vue/TypeScript,
existing VIVY SDK/Generation and native OS facilities.

**Spec:** [Existing shared ledger](../backend-separation-contracts.md#w3-go-host-contracts).
W3-3 speech functions, DTOs, media capability, raw routes, quotas and OS secret rules; retain C2 business speech meanings below the amendment.

**Status:** Blocked by W0 native caller/media/keyring contract.

**Immediate prerequisites:** W0.
The [index](../index.md#executable-story-package) owns live readiness.
**Requirement coverage:** W-R4, W-R5.

## Global constraints

Preserve single Runtime/Journal, sealed assembly, authenticated control/grants,
native sender identity and existing cancellation rules. No Agent rewrite,
historical import, second daemon, browser secrets/provider HTTP or permanent
dual host. Existing files listed below were verified against the frozen source
trees; proposed paths do not exist at that baseline. Reconcile source drift
before execution and serialize shared files. Tests/commands in this Plan are
future implementation gates, not results of this documentation publication.

## Tasks

### Task 1: Capture portable behavioral vectors

- [ ] Read current Rust provider/WAV/registry tests and closure-speech.json. Record exact model/base_url/text/audio/error constants and DTOs before porting. Keep deterministic mock-provider coverage separate from real provider evidence. Add Go vectors for invalid/corrupt/truncated WAV, quotas, config revision conflicts, request identity and cancel/late-settle races.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 2: Implement native stores and provider HTTP

- [ ] Use the W0-pinned OS keyring implementation with the documented namespace, no plaintext fallback and no secret readback to Vue. Preferences compare base_revision then atomically replace. Asset import uses opaque IDs, safe path containment and existing file/count/total caps; delete respects active leases. Provider requests use bounded body reads, explicit timeouts, verified endpoints and redacted diagnostics.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 3: Implement one cancellable speech service

- [ ] Bind identity to native window/context, session and generation; maintain per-request cancellation and bounded concurrency. Check identity at admission, before persistence and before returning/playback. Context replacement, hide, reload and quit invalidate requests. Late provider success after cancel must not persist audio, mutate assets or emit a playable result. Distinguish cancelled from already settled.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 4: Implement the binary media adapter

- [ ] Use W0-proven internal Wails routing; implement the W3-3 paths and token/header rules. Authenticate before reading expensive bodies, enforce 2 KiB metadata and media caps, reject foreign/revoked token and path traversal. Return typed JSON error bodies on non-success statuses; no listener daemon, raw filesystem path or browser provider endpoint.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 5: Expose the preserved frontend speech API

- [ ] Consume generated bindings for config/credentials/context/cancel/assets and same-origin raw media for bytes. Keep public speech.ts/controller behavior; serialize desktop-host.ts and module/lock edits with W3. The Go speech service is testable before W3 app composition and is connected to the single Desktop in W5.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Task 6: Verify provider and native failure paths

- [ ] Use local scripted HTTP providers for slow/oversize/error/redirect/late-success tests, OS keyring failures and asset contention. Then run configured SiliconFlow STT and SiliconFlow/MiniMax TTS with operator-held credentials outside committed fixtures. Record real provider request outcome and redacted metadata, not secrets. Keep unavailable cloud/native rows pending.
- [ ] Record the concrete result and relevant command/output in this Story's implementation log before proceeding.

### Final task: evidence, review and scoped commit

- [ ] Run the focused checks below and applicable repository-required gates.
- [ ] Review the diff against the shared ledger and this Story's exit criteria.
- [ ] Update this Story's evidence and the authoritative index from actual results;
      put unfixed findings in the owning backlog rather than calling them Done.

## Verification

Before runtime integration, run DIVA `go test -race ./internal/speech ./internal/desktop` on the independent speech/media packages. After W3 adds VIVY imports, use `python scripts/build-desktop.py --mode test` for the same Go checks under the staged modfile. Run `pnpm --dir agent-diva-gui test`. Run native keyring/media probe and configured-provider STT/TTS scenarios once the candidate is wired in W5.

Expected evidence: Go behavioral vectors match retained speech DTO/error/cancel semantics; forged sender, quota, slow/oversize provider, corrupt audio and post-cancel success fail correctly. Keyring and actual provider evidence are labeled by environment and source pins.

Record unavailable environments and the next concrete evidence owner as pending.

## 2026-06-26 (Channel simplification decision)
- **decision**: Channel architecture simplified to 7 first-class native adapters: Telegram, Discord, Email, QQ, Feishu/Lark, DingTalk, WeChat (new). Matrix and Neuro-Link remain but with limited/future-refactor status. WhatsApp, Mattermost, Nextcloud Talk, and IRC will be removed from native code (future plugin/bridge via ZeroClaw-compatible layer or Neuro-Link). Rationale: align with Agent Diva "minimalism" core principle and symmetric with provider simplification.
- **decision**: Slack is explicitly NOT first-class for v1.1; it may be re-evaluated later but will not be natively maintained in the simplified core. OAuth/web-login/cloud-IAM channels and social/content platforms remain out of scope.
- **decision**: WeChat adapter must be added as a new first-class channel; exact technical route (work app webhook vs. self-hosted bridge) requires further research under the constraint of no OAuth/web login.
- **change**: Decision document created at `docs/dev/channel-simplification-decision-2026-06.md` (also mirrored in agent-diva branch).
- **assumption**: Feature flags will be introduced per channel to reduce compile-time dependency bloat after the simplification.

## 2026-06-26 (Final quality bar decision)
- **decision**: Existing providers and first-class channels must be "production-complete", not minimally viable. All retained providers must support the full feature surface required by real usage (e.g., correct model routing, retry, fallback, rate-limit handling, token usage, tool schema support). All first-class channels must support group chat, file/media upload where the platform allows, QR/scan-based configuration where applicable, and complete inbound/outbound message flows. No adapter ships in a half-working state.
- **impact**: Channel simplification and provider simplification are now blocked on reaching this quality bar for every retained adapter. PRD acceptance criteria and roadmap updated accordingly.

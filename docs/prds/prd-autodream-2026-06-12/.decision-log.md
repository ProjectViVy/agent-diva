## Decisions

### D1. MVP 触发范围
- **Decision**: 手动触发 + auto 模式会话门（≥ 20 sessions，默认 off）
- **Rationale**: 最小可用，先验证核心价值
- **Owner**: 大湿
- **Date**: 2026-06-12

### D2. 审查模式
- **Decision**: 用户手动确认（缓存 + 决策）
- **Rationale**: 用户需要掌控记忆更新
- **Owner**: 大湿
- **Date**: 2026-06-12

### D3. AutoDream 与 mask 的关系
- **Decision**: 统一蒸馏，不隔离 mask
- **Rationale**: 先统一验证效果，再考虑隔离
- **Owner**: 大湿
- **Date**: 2026-06-12

### D4. 节律报告范围
- **Decision**: MVP 包含记忆候选 + 日报 + 周报
- **Rationale**: 完整展示节律价值
- **Owner**: 大湿
- **Date**: 2026-06-12

### D5. 失败通知
- **Decision**: 用户应收到通知
- **Rationale**: 失败不可静默
- **Owner**: 大湿
- **Date**: 2026-06-12

### D6. auto 模式设计（2026-06-12 增补）
- **Decision**: 新增 auto 模式会话门触发（≥ 20 sessions），默认 off，独立 toggle
- **Rationale**（大湿原话捕获）:
  > "auto 的 autodream 模式，默认不开启，设定阈值比较高一些，大概 20 轮对话...本质就是多轮对话了之后自动跨对话总结习惯，对于日报月报来说会生成更多的上下文"
- **设计对标**: Claude Code Auto Dream（24h + 5 sessions 双门，deduplication + contradiction removal + merging）
- **与 Claude Code 的差异**:
  - 阈值更高（20 sessions vs 5 sessions）
  - 单门触发（仅会话门）vs Claude Code 双门
  - 产物需用户审查 vs Claude Code 直接整理 MEMORY.md
- **边界澄清**（大湿原话捕获）:
  > "24h 这个功能要还给日周月报系统做处理，不是自动的"
- **影响**:
  - 时间门（24h）从 AutoDream 移除，归日报/周报/月报系统负责
  - Checkpoint 内容扩展为"成功时间戳 + 累计 sessions 数"
  - SelfEvolutionConfig 新增字段：`auto_mode_enabled` (default false) + `session_threshold` (default 20)
- **Owner**: 大湿
- **Date**: 2026-06-12

### D7. 与 Report System PRD 的边界（v1.1 修订）
- **Decision**: AutoDream = 数据压缩层, Report System = 用户呈现层。AutoDream 拥有日/周报**生成**, Report System 拥有月报 + 固化 + 搜索 + 展示层。
- **Rationale**: "autodream 只是一个压缩技术，而最终还是要回归到用户的可见内容中"（大湿原话）。概念正交, 两套子系统通过 markdown 文件路径契约解耦。
- **Owner**: 大湿
- **Date**: 2026-06-12
- **Reference**: `docs/architecture/scope-merge-decision.md`, Sprint Change Proposal 2026-06-12

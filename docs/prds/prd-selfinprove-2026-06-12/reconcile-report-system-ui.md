## Summary

selfinprove PRD v0.0.4 把"消费 AutoDream 候选 + 写 Laputa + 4 表面导航"主链路搭起来了, 但跟 report-system PRD v1.2 + UI research 比对, 还存在 12 类缺口。最严重的是 **产品 UI 表面基线缺位**——UI research 给出的 4 表面 + UiCard 11 字段 + 14 路由 + 10 SSE 事件 + 9 路径契约, selfinprove PRD 一条都没引用为契约基线, 处于"假设下游会接"型盲点。其次是 **Report System ownership 缺 back-link**——NotebookView 归 Report System 拥有 (commit `fcf768d`)、daily/weekly 展示层归 Report System 实际生成归 AutoDream (scope-merge)、月报归 Report System 全权 (独立 cron)、FR-8 写 MEMORY 走 pending.jsonl 降级, 这 4 条边界 selfinprove PRD 都没声明。固化流程 (FR-2xx) 仅有 outline, 缺 SOP 模板 / SKILL frontmatter 规范 / cherry-studio 范例的具体引用。5 核心流程中 rhythm wakeup 与 journal re-wakeup 端到端缺失, "old journal immutable + new follow-up entry" 跟 Report System §4.4 schema_version 升级条件无 back-link。Report System §6.1 诚实化的 P0-2 阻塞 (NotebookView 测试文件 / 覆盖率 / 设计评审) 是 selfinprove 升级 Journal 为批处理工作台的前置依赖, selfinprove PRD 也没声明。整体处于"假设上游已就绪 + 假设下游会接"的双重盲点, 落稿前需先固化 12 条契约 back-link。

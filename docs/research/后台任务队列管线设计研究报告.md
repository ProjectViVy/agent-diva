## 1. 执行摘要

| 框架 | 语言 | 后台任务模型 | 队列实现 | 定时任务 | 子进程管理 |
|------|------|-------------|---------|---------|-----------|
| **Alife** | C# | 事件驱动 + 轮询 | `ConcurrentQueue<string>` (Poke) | `PeriodicTimer` + `ITimeIterative` | ❌ 无 |
| **Hermes** | Python | 线程池 + 回调 | `queue.Queue` (completion) | `ThreadPoolExecutor` + cron parser | `subprocess.Popen` + Registry |
| **Diva** | Rust | `tokio::task` + async | `mpsc::unbounded_channel` (MessageBus) | `tokio::time::sleep` + cron parser | `agent-diva-sandbox` (5318 LOC) |

**核心发现**:
- **Alife**: 最简设计，只有 Poke 消息缓存队列 + 模块级定时轮询，**无通用任务队列**
- **Hermes**: 最成熟，线程池调度 + 进程注册表 + 双层限流通知，但受 GIL 限制
- **Diva**: 基础设施最好（tokio + mpsc + cron + heartbeat），但**缺通用后台任务队列/管线抽象**

### 2.2 核心组件

#### 2.2.1 Poke 消息队列 (`ChatBot.cs`)

```csharp
// 核心数据结构
readonly ConcurrentQueue<string> messageCache;  // 消息缓存
readonly SemaphoreSlim chatSemaphore;          // 聊天互斥锁 (1,1)
CancellationTokenSource cancelTimerSource;
int currentTime;
int lastAutoFlushTime;
const int DeltaTime = 1;  // 1秒tick

// Poke 入口
public void Poke(string message)
{
    while (messageCache.Count > 11)  // 队列上限11条
        messageCache.TryDequeue(out _);
    messageCache.Enqueue(message);
    lastAutoFlushTime = 0;  // 重置计时器
}

// 自动 flush（PeriodicTimer 驱动）
async Task TryFlushMessageCache(CancellationToken cancellationToken = default)
{
    if (messageCache.Count == 0) return;
    
    await RequestChatAsync(cancellationToken);
    try

        StringBuilder stringBuilder = new();
        foreach (string message in messageCache.Distinct())  // 去重
            stringBuilder.AppendLine(message);
        string poke = stringBuilder.ToString().Trim();
        messageCache.Clear();
        
        // 应用 PokeSend 过滤器链
        if (PokeSend != null) { ... }
        
        Chat($"{PokeMessageTag}\n{poke}");  // 触发聊天
    }
    finally { ReleaseChat(); }
}
```

**设计特点**:
- ✅ 线程安全：`ConcurrentQueue` + `SemaphoreSlim`
- ✅ 自动聚合：2秒窗口内所有 Poke 合并为一条消息
- ✅ 去重：`Distinct()`
- ❌ 无优先级
- ❌ 无持久化
- ❌ 无重试机制
- ❌ 容量硬编码（11条）

#### 2.2.2 模块定时轮询 (`ITimeIterative`)

```csharp
public interface ITimeIterative
{
    public void OnUpdate(ref float time);
    public float DeltaTime => 1;  // 默认1秒
}

// InteractiveModule.StartAsync() 启动后台循环
static async void StartUpdate(ITimeIterative handler, CancellationToken token)
{
    DateTime startTime = DateTime.Now;
    while (!token.IsCancellationRequested)
    {
        await Task.Delay((int)(handler.DeltaTime * 1000), token);
        float seconds = (float)(DateTime.Now - startTime).TotalSeconds;
        handler.OnUpdate(ref seconds);
        startTime = DateTime.Now - TimeSpan.FromSeconds(seconds);
    }
}
```

**设计特点**:
- ✅ 简单：每个模块独立轮询
- ✅ 可取消：`CancellationToken`
- ❌ 精度差：`Task.Delay` 不精确
- ❌ 无调度器：每个模块自己管理定时
- ❌ 无优先级/无并发控制

#### 2.2.3 SystemEventService 定时任务

```csharp
readonly (DateTime, Action)[] timeTask = new (DateTime, Action)[2];
// timeTask[0] = 自动报点定时器（指数退避）
// timeTask[1] = EWake 自定义提醒

public void EWake(DateTime time, string remark = "")
{
    timeTask[1] = (time, () => {
        Poke($"EWake报点：{remark}");
        timeTask[1] = (DateTime.MaxValue, () => {});  // 关闭
    });
}

public void OnUpdate(ref float seconds)
{
    foreach ((DateTime time, Action action) in timeTask)
    {
        if (DateTime.Now > time)
            action();
    }
}
```

**设计特点**:
- ✅ 简单：2个硬编码槽位
- ✅ EWait/EWake 自调度
- ❌ 无通用队列
- ❌ 无持久化
- ❌ 无重试/错误处理

#### 3.2.1 Cron 调度器 (`cron/scheduler.py`)

```python
# 并行/串行线程池管理
_parallel_pool: Optional[concurrent.futures.ThreadPoolExecutor] = None
_sequential_pool: Optional[concurrent.futures.ThreadPoolExecutor] = None

def _get_parallel_pool(max_workers: Optional[int]) -> concurrent.futures.ThreadPoolExecutor:
    global _parallel_pool, _parallel_pool_max_workers
    if _parallel_pool is None or _parallel_pool_max_workers != max_workers:
        if _parallel_pool is not None:
            _parallel_pool.shutdown(wait=False, cancel_futures=False)
        _parallel_pool = concurrent.futures.ThreadPoolExecutor(
            max_workers=max_workers,
            thread_name_prefix="cron-parallel",
        )
        _parallel_pool_max_workers = max_workers
    return _parallel_pool
```

**关键设计**:
- 有 `workdir` 的任务必须串行（`os.environ` 竞争）
- 无 `workdir` 的任务可并行
- 文件锁防止多进程并发 tick

#### 4.2.1 MessageBus (`bus/queue.rs`)

```rust
pub struct MessageBus {
    inbound_tx: mpsc::UnboundedSender<InboundMessage>,
    inbound_rx: Arc<RwLock<Option<mpsc::UnboundedReceiver<InboundMessage>>>>,
    outbound_tx: mpsc::UnboundedSender<OutboundMessage>,
    outbound_rx: Arc<RwLock<Option<mpsc::UnboundedReceiver<OutboundMessage>>>>,
    subscribers: Arc<RwLock<HashMap<String, Vec<OutboundCallback>>>>,
    event_tx: broadcast::Sender<AgentBusEvent>,
    running: Arc<RwLock<bool>>,
}

// 分发循环
pub async fn dispatch_outbound_loop(&self) {
    while *self.running.read().await {
        tokio::select! {
            Some(msg) = outbound_rx.recv() => {
                // 按 channel 分发，每个 callback 独立 spawn
                for callback in callbacks {
                    tokio::spawn(async move { future.await });
                }
            }
            _ = tokio::time::sleep(Duration::from_millis(100)) => {
                continue;
            }
        }
    }
}
```

**设计特点**:
- ✅ `tokio::sync::mpsc` — 无界通道
- ✅ `tokio::sync::broadcast` — 事件广播
- ✅ 每个 callback 独立 `tokio::spawn`
- ❌ 无背压控制（unbounded）
- ❌ 无优先级
- ❌ 无持久化

## 6. Diva 设计建议

### 6.1 核心缺口

```
Diva 当前已有:
├── MessageBus (mpsc + broadcast) ✅
├── CronService (定时任务) ✅
├── HeartbeatService (唤醒) ✅
├── Sandbox (子进程隔离) ✅
└── 缺: 通用后台任务队列/管线 ❌
```

### 6.2 建议设计：`TaskQueue` + `TaskPipeline`

```rust
// 建议新增：agent-diva-core/src/task_queue/

/// 通用任务定义
pub struct Task {
    pub id: Uuid,
    pub priority: TaskPriority,      // Low / Normal / High / Critical
    pub kind: TaskKind,            // OneShot / Periodic / Cron
    pub payload: TaskPayload,      // 具体任务数据
    pub retry_policy: RetryPolicy, // 重试策略
    pub timeout: Duration,
    pub created_at: Instant,
    pub status: TaskStatus,        // Pending / Running / Completed / Failed / Cancelled
}

/// 任务队列（多生产者单消费者）
pub struct TaskQueue {
    tx: mpsc::Sender<Task>,
    rx: Arc<Mutex<mpsc::Receiver<Task>>>,
    workers: Vec<JoinHandle<()>>,
}

/// 任务管线（链式处理）
pub struct TaskPipeline {
    stages: Vec<Box<dyn TaskStage>>,  // 如: Validate → Transform → Execute → Audit
}
```

### 6.4 具体建议

| # | 建议 | 优先级 | 说明 |
|---|------|--------|------|
| 1 | **引入 `TaskQueue`** | P0 | 通用任务队列，支持优先级/超时/重试 |
| 2 | **引入 `TaskPipeline`** | P0 | 链式处理（Validate → Execute → Audit） |
| 3 | **Worker Pool** | P1 | 限制并发数，避免资源耗尽 |
| 4 | **持久化队列** | P1 | SQLite/Redis，支持重启恢复 |
| 5 | **背压控制** | P1 | 有界 channel + 流控 |
| 6 | **任务审计** | P2 | 与 #5.5 审计集成 |
| 7 | **死信队列** | P2 | 失败任务隔离，人工介入 |

# GA 上下文密度 vs Diva C1–C5

- 状态：`Research Note / Not a Decision`
- 日期：2026-08-14
- 依据：论文 [`../papers/genericagent.md`](../papers/genericagent.md)（arXiv:2604.17091）；源码 `ee5a474`；Diva C1–C5 与 8/14 产品决策
- 性质：对比。不改已冻车道，不定 D0 方案。

用户判断：GA 表面因自主进化而火，**创举是上下文管理**。本页同意，并对照 Diva。

## 一句话

GA 把「有限窗口里决策相关信息密度」当唯一主轴。  
Diva C1–C5 把「稳定前缀、可测预算、安全/审批、可恢复」当主轴，密度是副作用。  
我们工程更完整，**默认塞进模型的东西更杂、更肥**；按需读得不如 GA 狠。

## GA 四件套（论文）

1. **工具要少**：9 个原子工具，组合出能力，不枚举技能接口。  
2. **分层按需**：常驻只留极短存在性索引（L1≤30 行）；事实/SOP 用 `file_read`。  
3. **巩固经验**：把已验证路径压成更短的 SOP/脚本，让**下一轮上下文更密**（实现比论文瘦）。  
4. **主动截断**：工具输出头尾截、旧标签压缩、FIFO 丢最老、每轮小 working-memory 锚。目标预算 ~30k。

自主进化在这个框架里是第 3 条的手段，不是独立产品。

## Diva 已经有、且不比 GA 差的

| 点 | Diva | 和 GA |
| --- | --- | --- |
| 分区与计量 | C1 类型化 section、C2 分层预算、AssemblyReport | GA 偏启发式字符预算 |
| 工具膨胀 | CORE / DEFERRED + `tool_search`（C4/C5e） | GA 靠天生 9 工具，几乎不需要发现 |
| 大工具结果 | artifact + 有界 preview，禁静默截断 | 头尾截断；大结果可落盘 |
| 长对话恢复 | 单一 `canonical_checkpoint_v1` | 压缩 + working 锚，无我们这套检查点合同 |
| 安全/多端 | sandbox、Approval、多 channel、GUI | 论文几乎不谈 |

这些要留。不要为了学 GA 拆掉可测性和安全。

## 没做到、或做得不好

1. **没有「密度」这根尺子**  
   我们优化 cache 稳定、hash、层预算。不问「这一轮决策真正需要的字占窗口多少」。结果是前缀合法、但是肥。

2. **常驻层过肥**  
   GA 常驻 ≈ 短 L1。  
   Diva 稳定前缀 = Mask + Frozen Core + Skills + Memory L1 索引 + **整表 CORE 工具 schema**。  
   Frozen Core 有产品理由（人格永冻）。Skills 全文和偏大的 CORE 表，是密度上最大的亏。

3. **按需读不彻底**  
   GA：L2/L3 默认不进，要读再读。  
   Diva：BML 有索引注入 + PrefetchRecall；人格生产路径仍可能把 JSON 段塞进 FC；WORLD 已改工具（这点和 GA 一致）。  
   ACTMEM 正文不装配、只留一个查询工具——**方向对**，但还没落地，跨会话近事目前既没有密的常驻锚，也没有可用的 `actmem`。

4. **没有「每步一句话的活动锚」**  
   GA 每次工具后塞极短 `key_info` + 近 20 条一行摘要，压缩丢历史也不丢当前目标。  
   Diva 的 `WorkingMemory` 是 session BML 行，结束就删，且不是这种逐步锚。  
   CanonicalCheckpoint 是压缩后的大块，不是逐步密锚。  
   产品 ACTMEM 又整份走工具：活动集**默认看不见**。这是完整性和简洁性里，我们偏简洁、赌模型会查。

5. **工具最小性没当原则**  
   DEFER 减轻了枚举，CORE 仍偏多。GA 把「少工具」写成进化的前提：经验固化成组合原子工具的 SOP，而不是新工具。  
   我们容易走反：功能来了就加常驻工具（BML CRUD 就是教训）。ACTMEM「查询 CORE、管理 DEFER」是在纠偏。

6. **巩固没有变成「让下次上下文更短」**  
   GA 写 SOP 的目的是下次少探索、少字。  
   Diva AutoDream 默认 `MemoryPatch` / 提案，是往系统里**加治理对象**，不是给下一轮减负。  
   这不是上下文模块的锅，但会把窗口越养越脏。

7. **观测压缩偏工程、偏语义不足**  
   artifact 很好。GA 还有浏览器 DOM 剪枝、标签级压缩、每五轮压旧 thinking。  
   我们缺少「这一步观察里什么对决策有用」的统一压缩纪律。

## 怎么说（对外/对内一句）

Diva 的上下文是 **生产级装配与安全合同**；GA 的上下文是 **密度操作系统**。  
我们缺的不是再加一层存储，是：常驻只留「存在性 + 人格永冻」，其余按需；工具默认少；巩固是为了减负，不是为了多一份提案。

已冻决策里，和这条对齐的：WORLD 工具、ACTMEM 不装配、查询一个 CORE、管理 DEFER。  
还没对齐的：前缀仍然偏肥、活动锚没有、AutoDream 仍按旧合同产 MemoryPatch、CORE 工具仍然偏多。
